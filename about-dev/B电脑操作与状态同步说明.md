# B 电脑操作与状态同步说明

## 目的

B 是第一阶段的 Agent 执行节点，负责读取项目、修改代码、运行本地测试和记录结果。A 只负责提交任务、查看状态和补充必要配置。

## B 当前环境

- Windows 11
- 40GB 内存，i5-13400
- 已安装 Docker、WSL2、Git、Python、Node
- C 盘空间已完成检查
- 项目位于 B 电脑指定目录
- 本地项目内包含 MCP 模块，本地测试不连接生产 MCP

## B 上的操作顺序

1. 打开本项目工作区。
2. 读取 `/plan/多机Agent项目实施计划.md`。
3. 读取 `.agent-state/environment.md`、`.agent-state/current-task.md` 和 `.agent-state/latest-result.md`（如果存在）。
4. 检查当前 Git 状态，不覆盖已有修改。
5. 读取项目说明、依赖配置、启动脚本和测试入口。
6. 执行当前任务需要的最小操作。
7. 将环境检查、任务进度和测试结果写回 `.agent-state/`。
8. 在计划文件中同步标记已完成事项。

## 状态文件

```text
.agent-state/
  environment.md       # B 的环境和项目运行方式
  current-task.md      # 当前任务说明和执行状态
  latest-result.md      # 最近一次测试和交付结果
  blockers.md          # 需要人工提供的配置、权限或业务信息
```

状态文件不得包含 API Key、密码、Token、Cookie 或其他个人凭据。

## A、B 同步规则

- 聊天记录只作为任务说明，不作为唯一状态来源。
- 项目代码、计划文件和 `.agent-state/` 是工作状态的基准。
- B 完成检查或任务后，必须先更新状态文件，再向聊天报告结果。
- A 修改任务后，应更新 `current-task.md`，再让 B 继续执行。
- 如果使用 Git，同步顺序为：B 拉取最新内容 → 执行 → 提交状态和代码 → 推送；A 查看或继续前先拉取。
- 如果尚未配置 Git 远程仓库，先使用文件复制或共享目录，不把 A 和 B 的聊天内容当作同步机制。

## B 上的安全边界

- 第一阶段只操作本地项目和测试环境。
- 不连接生产 MCP。
- 不修改 C、E 生产服务器。
- 不执行未明确授权的生产部署、数据写入或服务重启。
- 不安装新依赖或迁移 Docker/WSL 数据，除非计划中已记录并得到确认。
