# 多机 Agent 项目实施计划

## 1. 项目目标

先在 B 电脑上跑通一个真实项目的 Agent 开发闭环，再通过 Tailscale 连接 A、B 和后续 Worker，逐步增加任务调度与多 Agent 协作。

第一阶段只关注本地开发和测试，不接入员工入口，不自动操作生产环境。

## 2. 已确认条件

- A：日常 PC，用于提交任务和查看结果。
- B：Windows 11、40GB 内存，已安装 Docker、WSL2、Git、Python、Node，用于代码修改和本地测试。
- B 的 C 盘剩余约 3GB，安装新依赖前必须检查并处理磁盘空间。
- C、E：生产 Linux 服务器，第一阶段保持现有职责。
- D：转发 Linux 服务器，后续可作为调度中心候选。
- F：备用 Windows PC，第二阶段再启用。
- New API：位于美国 Linux 服务器，支持多并发。
- 本地项目内含 MCP 模块，本地测试不连接生产 MCP。
- 代码问题由 Agent 处理；缺少账号、权限、证书、环境变量或业务规则时再请求人工处理。
- A、B 使用 Tailscale 组网，不要求处于同一局域网。

## 7. A、B 状态同步方式

- 聊天记录可以在同一账号的 Codex 会话中继续，但机器本地的命令输出、配置、运行日志和进程状态不会自动同步。
- B 作为执行机器时，任务结果必须写入项目工作区或调度中心，不能只留在 B 的聊天记录中。
- 第一阶段使用项目内的 `.agent-state/` 目录保存任务摘要、环境检查结果和最后一次测试结果；密钥、Token 和个人凭据不得写入该目录。
- 进入下一步前，以 B 上的实际文件和运行结果为准；A 上的聊天只作为任务说明和查看入口。
